# 人物模型与动画资源选型

核查日期：2026-09-20。本文是第二阶段的资源调研和推荐方案；本轮未下载、购买、导入或制作人物资源。

## 目标与建议

目标是**成人真实比例、轻度风格化的人类角色**：能辨认头脸、头发、手脚、衣服和鞋，近距离看背部也自然；不要求照片级皮肤、毛发、面部表情或布料模拟。摄像机是第三人称右肩后上方视角，因此背部轮廓、肩颈、步态与蹲姿比面部细节更优先。

不需要先从零给四个人建模。建议先完成**一个可换装的人体样板、一套共用骨架，以及走路、蹲行、冲刺、翻滚的验证**，通过后再派生玩家与三位领导。各角色通过衣着、发型、体型小幅变化区分；先保留同一骨架结构与相近比例，避免重复适配动画。

建议优先试验 **Blender + MPFB 成人角色 + Quaternius 的 CC0 动画库**。这条路更贴近本项目的人物目标，并便于将可再分发的资源纳入 Git。若人体整理耗时过大，可以先用 Quaternius 的人体做控制器样板，再替换外观。此建议是结合项目目标作出的选型判断，不代表两种资源已经在本项目完成兼容测试。

### 衣服与人物外观

MakeHuman 官方资源包目录分别标注 CC0 与 CC-BY，并非目录内所有资源都是 CC0。适合优先检查的 CC0 包有 `Suits 01`、`Shirts 01`、`Pants 01`、`Shoes 01`、`Hair 01`、`Glasses 01`；具体衣物风格及蹲姿穿插仍需导入后查看。使用 CC-BY 资源时，要保留对应作者、许可链接及修改说明。参考：[官方资源目录](https://static.makehumancommunity.org/assets/assetpacks.html)、[资源包许可说明](https://static.makehumancommunity.org/assets/assetpacks/faq.html)。

人物方向建议：玩家穿普通上衣、长裤、运动鞋；三位领导分别使用衬衫、外套、西装等轮廓，避免仅靠颜色辨认。第一版只需一个玩家外观，不增加捏脸或角色选择界面。

### Mixamo 与公开仓库

Adobe 官方帮助页明确允许将角色和动画用于游戏，但这不等于允许公开发放可复用素材。Adobe 社区中的许可 FAQ 将原始角色/动画的自由分发列为不允许，并区分项目团队内部协作与向其他人分发。该页是**Adobe 社区内容，不应当作为正式合同全文**；本次查到的官方 Mixamo 附加条款也不能单独证明公开原始素材已获授权。

因此本项目的资源管理建议是：如果未来确实选用 Mixamo，将源文件保存在项目团队受控位置，公开仓库保留导入流程和资源获取说明；不要认为 FBX 改成 GLB、Godot AnimationLibrary 就自动获得了再分发许可。优先使用 CC0 资源可以减少这一限制。来源：[Adobe 社区许可 FAQ](https://community.adobe.com/questions-696/mixamo-faq-licensing-royalties-ownership-eula-and-tos-589400)、[Mixamo 附加条款](https://wwwimages2.adobe.com/content/dam/cc/en/legal/servicetou/Mixamo-Addl-Terms-en_US-20210623.pdf)。

## 动画能否直接找到

不能把“有动画库”理解为“免费下载后恰好包含所有需要的动作”。核查到的作者页面说明如下：

| 动作 | 目前能确认的范围 | 后续验证 |
|---|---|---|
| 待机、普通行走 | Quaternius 动画库提供 locomotion；具体文件、方向和免费档覆盖未逐个查看 | 检查循环、脚底接地与左右转向 |
| 冲刺 | 作者明确列出 sprint；不能据此保证所需版本位于免费 Standard 包 | 确认具体 clip、免费/付费档、速度与游戏位移一致 |
| 蹲下慢走 | 本轮未核实具体蹲行 clip；页面提到 crawling，不能把爬行当蹲走 | 检查蹲下、蹲姿待机、蹲走及站起是否齐全 |
| 蹲姿翻滚 | 本轮未核实合适的具体 clip；Library 2 提到 parkour，不足以证明有需要的翻滚 | 必须能从蹲姿进入并回到蹲姿，必要时剪辑/补关键帧 |

作者的 [Universal Animation Library](https://quaternius.itch.io/universal-animation-library) 包含关闭/开启 Root Motion 的版本；[Library 2](https://quaternius.itch.io/universal-animation-library-2) 是补充库。两者完整商品页的动作总数不等于免费档拥有的数量，本轮不承诺动作齐全，也未实测 Mixamo 中任何指定动画。

若某个动作缺失，先在可再分发许可的库中补找，再考虑针对共用骨架制作少量关键帧；不因暂缺翻滚就批量导入不同骨架的人物。

## Godot 接入计划

1. **固定一个人体样板。** 保存可编辑的 Blender 工程，另导出游戏用 GLB。优先一套简化材质和贴图，不把 Blender 的复杂程序材质直接视为可导出结果。
2. **统一骨架与尺寸。** 检查比例、朝向、骨架静止姿势和骨骼映射。Godot 提供 `BoneMap` 与 `SkeletonProfileHumanoid`；同名骨骼不代表可以直接共用动画。
3. **先验证待机、行走。** 动画导入为可共用的 AnimationLibrary，检查脚底滑动、肩膀扭曲和服装穿插，再增加蹲行、冲刺、翻滚。
4. **先采用代码控制移动、原地动画配合位移。** 这是本项目的实现建议，便于继续使用角色碰撞和移动逻辑。翻滚的时长、位移和结束姿势单独对齐；如果改用 Root Motion，需要重新验证碰撞。
5. **动作和碰撞分别实现。** 蹲姿需要真实降低角色碰撞体和受观察点，站起时检查头顶空间；播放蹲下/翻滚动画本身不会实现这些规则。
6. **验证样板后才做角色变体。** 复用骨架和动画，单独检查每套衣服在蹲下、跑步、翻滚时的变形。

Godot 官方说明支持使用 glTF/GLB，并提供人体动画重定向流程。MPFB 官方建议针对游戏引擎使用 `GameEngine` 材质和骨架，并清理辅助几何或采用低面数代理；这些措施仍需要在本项目的 Godot 版本中验证。参考：[Godot 3D 格式](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html)、[Godot 骨架重定向](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/retargeting_3d_skeletons.html)、[MPFB 导出说明](https://static.makehumancommunity.org/mpfb/docs/exporting.html)。

## 样板验收与资源记录

- 右肩镜头距离下，能清楚认出成人身体比例、手脚、发型和服装；不要求面部动画。
- 同一个样板能完成站立、行走、蹲行、冲刺、翻滚，切换时无明显扭曲、悬空或服装露出身体。
- 蹲姿与翻滚均经过碰撞、低矮空间、遮挡和站起空间验证；镜头不跟着翻滚旋转。
- 在 Mac 和 Web 各验证一个玩家加三位领导，记录帧率和包体变化。先以每人约 1–2 万三角面、1K 贴图作为试验预算，是否足够以实测为准。
- 每个实际采用的资源记录作者、下载页、下载日期、包版本、许可文件和修改内容。仓库中只提交允许再分发且运行实际需要的文件。

本阶段的第一项实际资源任务应当是“完成一个人体样板的动作接入”，而不是“先做完四个精细角色”。
