日期：2026-09-23。工程：Godot 4.7.2，Compatibility，GDScript。入口 `res://scenes/release.tscn`，版本 `1.0.1`；本地预览端口 `8772`。

**状态：1.0.1 本地稳定性验证与交付已完成，尚未上传或公开。** 已落实方向键自由观察，并修复视线提示频闪、贴墙镜头瞬跳与角色淡出卡顿。引擎、Chrome 最终实载包、原生连续画面和应用启动分别验证；真实 itch.io 托管仍待账号或页面。以下通过数只属于所标明的版本与检查范围。

## 范围与基线

- 1.0.0 已提交 `168f0cb`，其引擎 92／92、Chrome 整关 67／67、另轮菜单 26／26 与 macOS 构建证据保留在 [P5–P6 交付测试记录](P5-P6交付测试记录.md)。旧包摘要不对应修改后的 1.0.1。
- 本轮增加方向键上下俯仰／左右环绕，W/S 前后、A/D 人物转向，保留右键拖动、滚轮与 F。
- 为兼顾易玩，默认松开观察后暂留 1.25 秒；未继续移动或转身则保留视角；移动触发后平滑完成回正，方向键或右键观察可随时打断。F 恢复人物后方与默认 14° 俯角，保留镜距。参数仍可调整。
- 排查三位领导、尤其工位组长视线提示的闪烁；不能通过改变实际感知规则、掩体或发现时间掩盖问题。
- 本轮不增加关卡、巡逻、追逐或新动作，不上传或公开发布。

|---|---:|---:|
| 站立待机 | 4 | 2 |
| 行走 | 12 | 4 |
| 跑步 | 18 | 5 |
| 蹲姿待机 | 2 | 2 |
| 蹲走 | 49 | 20 |

扇面位于地面上方 0.026 m，地板顶面为 0；此次排查未发现两者共面，因此不能把这次问题归为 P1 曾修复的墙面深度争抢。最终修复使用稳定的连续垂直包络：站姿 0.98～1.60 m、蹲姿 0.64～0.81 m、翻滚及恢复 0.07～1.32 m、蹲起过渡 0.64～1.60 m。每格至多检查上下端两条射线；只有两端被同一个凸形状挡住，才把整个区间判为遮挡，否则保守显示潜在风险。这使薄桌面等不同遮挡物之间的空隙不会被离散高度采样遗漏。站蹲切换、翻滚与起身过渡仍立即切换对应包络，移动遮挡物仍按原刷新节奏更新；相同结果复用已有网格，不随呼吸和骨骼起伏反复重绘。

黄色区域仍是有限采样的保守方向提示，并非精确安全边界。领导是否真正看见玩家、0.35 秒确认及失败仍由实际动画头胸点、眼位和碰撞射线决定，不用提示网格代替真实感知。三位领导 × 六段动作 × 每段 121 个相位的最终几何回归全部为 0 次变化、1 种网格且复用相同网格对象；与旧动态高度提示逐格对照，原先亮起的单元遗漏数为 0。专项共 70／70 通过，见 `.logs/release-guard-cue-after.log` 和 `.logs/release-guard-cue-after.json`。这项检查使用固定位置和受控动作相位，用于隔离提示变化；原生提示专项已完成，Chrome 对应提示画面也已检查；视线提示与角色淡出长帧分别复验，最终本地验证均已完成。

### 连续画面与淡出卡顿诊断

最终源码原生提示专项 73／73，通过三个场景各 90 帧、共 270 帧检查；最新日志 `/tmp/xiaban-guard-cue-native-final.log` 无 ERROR／WARNING，像素统计绑定最终 `6f9ae7…` PCK 摘要。站姿固定区域 `[800,550,1050,615]` 与蹲姿固定区域 `[40,410,390,480]` 各 90 帧，相邻帧像素差均为 0；报告 `.logs/release-guard-cue-native/report.json`，区域统计 `pixel-stability.json`。它们验证受控视线区域的静态稳定，不表示整幅人物动画画面应该不变，也不替代最终导出应用启动。

连续包络中间包 `0e73c1…` 的 Chrome 专项 32／32，低柜可见区域 `[80,420,350,610]` 的 7 张截图产生 6 次相邻比较，像素差均为 0；证据已保留到 `.logs/release-browser-stability-0e73c1-intermediate/cue-pixel-stability.json`。同包完整 Chrome 67／67 属于淡出修复前的整合回归，不标为最终 PCK 通过数。

该中间包贴墙镜头采样仍有卡顿：录屏轮 7.66 秒、440 帧，平均 57.26 FPS，出现 3 次约 133 ms 长帧。随后关闭录屏重复两轮，仍分别出现 4／3 次超过 40 ms 的帧，最大约 200／151 ms，时间点对应角色淡出模式切换，排除了仅由录屏引起的解释。旧报告保留于 `.logs/release-browser-camera-frames-0e73c1-before-fade-fix/`。

Godot 4.7 的 `BaseMaterial3D::_update_shader()` 在旧材质键最后一个用户释放后，会释放并移除对应着色器缓存；保留同键用户则可复用已有资源，参见 [Godot 官方源码](https://github.com/godotengine/godot/blob/4.7/scene/resources/material.cpp)。结合淡出切换时重复长帧的复现，本轮只让正式玩家在衣装注册完后复制并强引用不可变 HASH 材质变体，通过 `get_rid()` 初始化资源，保持其生命周期；实际淡出计算、原衣装材质与头发镂空恢复不变。保留资源解决重复释放；仅创建材质还不能准备其实际 GPU 绘制路径。因此最终版本另在开始游戏前完成真实绘制准备：相机稳定后，在遮罩下画一帧玩家淡出与使用真实视线材质的临时三角形，再恢复人物并完成下一帧。准备完才开放开始按钮、Enter 焦点和只读 QA，随后移除临时几何。此过程不推进领导状态或计时，不改变历史样板和三位领导材质。

材质资源专项最终复跑 7／7（`/tmp/xiaban-fade-shader-final.log`）确认完整衣装变体保留、重复调用幂等、12 轮淡出恢复资源不变、纹理和镂空特征保留；完整引擎最终 94／94（`/tmp/xiaban-release-warmup-regression.log`，无界面模式跳过 GPU 准备，实际 GPU 路径另由 Chrome 与原生验证）。资源保留后又加入启动绘制准备，对应最终 PCK `6f9ae7…` 的无录屏两轮严格 40 ms 阈值检查已通过，结果见下表。最终浏览器专项、真实键鼠路线与启动／嵌入烟测均已完成，结果独立列在下方；最终原生应用启动与画面复核也已完成。中间包 67 项不计入最终 PCK 的通过数。
