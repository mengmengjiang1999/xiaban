# 第一关任务清单

> 本页是第一阶段斜俯视 v0.1 的任务与验收归档，对应 `2D-version`。2026-09-20 起的过肩镜头、蹲走和翻滚安排见 [当前开发计划](../开发计划.md)；下文“不加入蹲伏”等范围只适用于旧阶段。

更新日期：2026-09-19<br>
目标：完成一关可以独立开始、成功下班、失败并重试的 3D 办公室潜行游戏。

当前状态：第一关 v0.1 功能与技术回归已完成；外部试玩、跨环境验证和公开上传保留待办。

本清单把 [第一阶段开发计划](../开发计划-v0.1归档.md) 拆成逐阶段可执行的工作；地图与体验安排见 [第一关设计](第一关设计.md)。
复选框记录对应工作的进度；D0 勾选仅表示形成设计初稿，不代表相关游戏功能已经实现或玩法已经验收。
M0 已有的环境验证证据及兼容性补测项仅见 [M0 测试记录](M0测试记录.md)。

## 使用方式

- 按 D0 → M1 → M2 → M3 → M4 → M5 → M6 推进，每阶段先做任务，再实际游玩验收。
- 未通过的验收要记录现象并调整；通过前不靠增加家具、模型或关卡长度掩盖问题。
- “灰盒”就是先用方块、胶囊等简单几何体搭场景，测试路线和规则，再替换成模型。
- 视野角度、速度、警戒时间和地图尺寸都属于待试玩调节的参数，草图数字不是最终值。
- 新想法先记到后续待办；本轮只完成既定的一关，不加入道具、蹲伏、联机等功能。

## D0：把第一关画清楚

**依赖：**已确认的 [项目设定](../项目设定.md)。

- [x] 画出工位、办公区、领导办公室、走廊和楼梯入口的俯视草图（v0.1）。
- [x] 标明玩家起点、出口、可走通道，以及挡路的矮桌和挡视线的高掩体。
- [x] 标出三位领导的初始位置、朝向、转头或巡逻安排。
- [x] 为三段挑战各安排观察位置、预期通过时机和暴露后的退路（待原型实测）。
- [x] 沿预期路线逐段检查，确认楼梯口领导有可提前看见或听见的提示。

**可体验成果：**在草图上模拟一次从工位到出口的行动，解释每次停下观察的原因。

**验收：**能指出一条完整通路，并说清三段挑战分别教会玩家什么；出口前有观察机会。
地图不要求等待不可能出现的空隙；暂时无法从草图确定的尺寸、节奏和视野重叠列为原型验证项。
设计文档记录为什么这样布局，并能直接作为 M1～M4 搭建的依据。

## M1：玩家移动、镜头与碰撞

**依赖：**D0 的路线意图与 M0 可运行工程；先做小测试场，不搭完整地图。

- [x] 使用胶囊角色实现 WASD 移动、转向和 Shift 跑步，方向以镜头地面方向为参照。
- [x] 处理斜向速度，使斜着走不会比直走更快；跑步只增加速度。
- [x] 放置地面、测试墙和矮桌，为玩家与障碍物配置碰撞。
- [x] 加入斜俯视跟随镜头，保证角色和即将经过的通道可见。
- [x] 导出一次 Web 版本，检查键盘输入与移动在浏览器中生效。

**可体验成果：**可以操控胶囊在墙、桌子和通道间自由移动。

**验收：**依次直走、斜走、跑步、松开按键，方向与速度符合预期，停止后不持续滑行。
沿墙走、顶住桌角再换方向，不能穿过障碍、卡死或掉出地面；镜头跟随无明显抖动。
在本地服务器打开 Web 构建，重复上述操作，记录与编辑器中的差异。

## M2：一位领导的视野与警戒

**依赖：**M1；只放一位固定领导，先验证感知规则。

- [x] 建立可复用的领导场景与配置，集中管理距离、角度、警戒增长和消退参数。
- [x] 同时检查距离、朝向夹角和遮挡，决定玩家是否被看到。
- [x] 实现暴露时增加警戒、脱离视线后按规则消退，并显示当前警戒状态。
- [x] 绘制可见的地面视野范围，显示和实际检测共用配置与遮挡规则。
- [x] 用墙、高隔断、矮桌和掩体边缘分别验证感知与显示。

**可体验成果：**玩家可以主动走进危险区域观察警戒上涨，再退回高掩体后观察变化。

**验收：**在正面范围内无遮挡暴露时警戒上涨；背后、距离外和高墙后不累计警戒。
站在矮桌后仍可能被看到；高掩体会截断地面视野，不能出现“显示安全但实际被看到”。
从掩体边缘反复进出，显示与检测保持可解释的一致性，不出现明显无规律闪烁。

## M3：追赶、导航与最小胜负循环

**依赖：**M2；保留小房间、一位领导和一个出口，先验证完整玩法。

- [x] 警戒满后进入追赶，先让领导在测试房间绕过桌子追人，验证导航路径。
- [x] 失去视线后前往最后发现位置，短暂等待再返回；状态变化给出清楚提示。
- [x] 在距离足够近且无墙体阻隔时捕获玩家；加入出口区域和统一的胜负结算。
- [x] 加入开始、成功、失败和重试界面，重试恢复玩家、领导、警戒与界面初态。
- [x] 加入暂停与继续，提供可点击入口；暂停时停止角色、领导和警戒更新。
- [x] 实际玩出成功、被抓、摆脱追赶三种过程，确认值得继续扩成完整关卡。

**可体验成果：**一个有起点、危险、出口、胜负和重试的小型可玩关卡。

**验收：**把桌子放在领导与玩家之间触发追赶，领导能绕路，不穿桌、不无限顶着桌子走。
躲到墙后使领导丢失目标，观察它到达最后位置并返回；隔着薄墙不能仅因距离近被抓。
分别触发成功和失败并重试，再在追赶中暂停后继续，确认状态完整恢复且没有重复结算。
记录出口与捕获同时发生时的结果，按现有计划验证捕获优先，结果不能随事件顺序变化。

## M4：扩成三段完整第一关

**依赖：**M3 验收通过，尤其是绕桌追赶与完整重试；使用 D0 草图搭建。

- [x] 用灰盒搭出办公区、领导办公室、走廊和楼梯入口，连接起点与出口。
- [x] 复用同一领导场景，通过配置区分工位转头、办公室巡逻和楼梯口巡逻。
- [x] 设置观察位置、高掩体、等待位置与巡逻点，检查转角和通道宽度。
- [x] 为完整布局配置导航，检查桌椅、门口和窄道中的追赶与返回。
- [x] 给楼梯口领导加入提前可察觉的线索，并保留可观察、可避开的空间。
- [x] 从起点完整通关，按试玩结果调整布局、视野和节奏，不把参考时长当硬性指标。

**可体验成果：**玩家可以从工位一路经过三段挑战，到楼梯入口成功下班。

**验收：**不借助调试移动、不关闭领导检测，实际完成一条通关路线。
三位领导的规律可区分，观察、等待和掩体各有作用；楼梯口不能成为无法预判的必输陷阱。
让两位领导同时发现玩家，检查追赶、警戒显示和单次结算；在关键位置失败重试能恢复同一起点。

## M5：让新玩家看懂并愿意重试

**依赖：**M4 完整路线可玩；先保留已验证的碰撞、遮挡和导航规则。

- [x] 把关键几何体替换为简单人物与办公家具，统一配色并记录外部素材来源与授权。
- [x] 加入基础待机和移动表现、脚步声、警戒音，以及简短的成功失败反馈。
- [x] 补操作与目标提示，用文字或图标配合颜色区分安全、怀疑和追赶。
- [x] 完善开始、暂停、继续、重试、音量和返回主菜单，并通过开始操作启用网页音频。
- [ ] 完成所有环境的镜头、窗口、焦点与 Esc/全屏验收（当前 Chromium 画面、暂停、窗口与全屏入口已检查；原生 Esc 退出全屏和其他浏览器待补）。

**可体验成果：**玩家能辨认办公室、自己、领导、掩体和出口，并理解失败原因。

**验收：**让未参与开发的人根据屏幕提示开始游戏，观察其能否理解移动、躲避和目标。
实际被发现一次，确认无需开发者口头补充也能理解原因；静音时关键危险仍有可见提示。
替换模型后再经过窄道和高掩体，确认不会出现看似能通过却被卡住、看似遮挡却暴露的问题。
切换标签页、调整窗口、进入和退出全屏，返回后状态清楚，不发生无人操作时的后台误捕获。

## M6：试玩修正与 Web 交付

**依赖：**M5；这里交付可上传的原型，公开 itch.io 发行单独执行。

- [ ] 邀请试玩者记录首次理解、失败原因、卡住位置和重试意愿，优先修复阻断问题。
- [ ] 完成 Web 包全部手动验收（已导出并验证浏览器加载、开始、暂停、重试、菜单和画面；完整胜负通过引擎实际输入回放，网页长按及声音感受待人工补测）。
- [ ] 检查目标浏览器并记录系统、浏览器和结果；补测 Safari，不用 Mac 结果代替 Windows 验证。
- [x] 整理 Web ZIP、工程源码、运行说明、已知问题、版本记录和素材授权清单。
- [x] 准备 itch.io 页面草稿所需的封面、实际游戏截图、操作说明及已验证的兼容范围。

**可体验成果：**试玩者脱离编辑器打开网页，即可独立完成整关。

**验收：**至少有未参与开发的试玩者完成开始、失败、重试和成功，且不存在已知阻断流程的问题。
最终 ZIP 能在本地服务器正常运行；缺失的浏览器或设备验证明确标为未测，不扩大支持声明。
游戏在浏览器无法持久保存设置时仍能游玩，声音和窗口变化不会破坏流程。
交付物与说明保持一致；后续上传到 itch.io 后，必须另做实际托管页面的完整游玩验证。
